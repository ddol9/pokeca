## Problem Statement

수집가는 특정 카드(예: sv2a 201/165)에 맞는 확장 아트 도안이 존재하는지, 어디 있는지 찾을 수 없다. 도안은 카페 글·댓글·드라이브 링크에 흩어져 있고 카드 번호로 검색되지 않으며, 찾은 파일도 보관이 어렵다.

원 기획안은 "핵심은 규격 프로파일과 인쇄 엔진"이라고 정의했지만, 세션에서 확인된 고통은 인쇄 적합성이 아니라 **발견(카드 번호 → 도안)과 보관**이다.

## Demand Evidence

- "커뮤니티에서 자작 공유 중, 실제로 카페에서 커미션을 받고 무료로 제작해주는 아티스트들이 존재함" — 공급 측 행동 증거. 아티스트가 돈 없이 요청을 받아 그린다.
- 시장 존재: Etsy에서 카드별 9포켓 바인더 확장 아트 PDF가 약 $6.75에 판매 중(A4/Letter 버전 제공), PSA 슬랩 스킨 실물은 $13~16.
- 아직 없는 것: 카페 규모, 월 요청 수, 아티스트 수 같은 숫자. 수집가가 "사라지면 곤란해질" 수준의 의존 증거.

## Status Quo

- 수집가: 카페에서 글을 뒤지거나 요청 글을 쓰고 기다린다. 카드 번호로 검색할 수 없다.
- 고른 고통(verbatim): "파일 찾기·보관이 어려움, 원하는 카드에 대한 알맞은 디자인 찾기가 어려움".
- 고르지 않은 고통: "인쇄하면 사이즈가 안 맞음", "아티스트 공급 부족", "도용·무단 재배포". 단, Etsy 판매자들도 "바인더 브랜드별 포켓 크기 차이로 재단·스케일 조정이 필요할 수 있음"을 명시하므로 규격 문제는 존재하나 1순위 고통은 아니다.

## Target User & Narrowest Wedge

- 1호 사용자: 창업자가 아는 수집가 한 명. 고통: "원하는 카드 번호에 해당하는 그림을 찾기 어려움". (이름·최근 실패한 카드 번호는 아직 미확보 → Assignment)
- 공급 측: 카페에서 무료로 요청을 받아 그리는 아티스트들.
- 가장 좁은 쐐기: 수집가가 찾는 카드 번호를 치면, 그 카드에 맞는 기존 도안이 아티스트 이름과 함께 나오는 페이지. 신규 작품 제작·인쇄 엔진 없이 성립한다.

## Constraints

- 1~2인 개발, TypeScript 단일 스택(원 기획안 유지).
- 포켓몬 IP: 공식 카드 이미지를 표시하지 않는다. 비영리 운영. 내림 요청 절차를 첫날부터 둔다.
- 장기 목표는 사업화. 단, 아래 전제 3에 따라 포켓몬 IP 위에 직접 수익을 붙이지 않는다.

## Premises

1. 진짜 문제는 발견(카드 번호 → 도안)이다. MVP 중심은 카드-도안 인덱스이며 인쇄 엔진은 2순위다. — 동의
2. (Codex 반론 후 수정) 초기 병목은 신규 아티스트 모집이 아니라 **이미 존재하는 작품의 수집·카드 번호 매핑·게시 허락**이다. 초기에는 창업자가 직접 큐레이션하며, 아티스트에게 추가 작업(템플릿 재작업, 재업로드)을 요구하지 않는다. — 동의
3. 포켓몬 IP 위에 직접 수익(수수료, 광고, 공개 모금)을 붙이는 사업화는 서비스를 끝낼 수 있다. 사업화는 IP와 분리된 층(IP 중립 규격·인쇄 도구, 다른 TCG, 오리지널 아트)에서 한다. 근거: Relic Castle DMCA(2024-03, 직접 호스팅하지 않았는데도), 전 TPC 법무 책임자 "모금과 언론 노출이 단속을 부른다". — 동의
4. 12주 전체 플랫폼 이전에, 1~2주 내 아는 수집가와 카페 아티스트 몇 명으로 검증 가능한 쐐기를 먼저 낸다. — 동의

## Cross-Model Perspective

Codex(독립 콜드 리드) 요약:
- Steelman: "판매 플랫폼이 아니라, 카드 번호를 입력하면 해당 카드에 맞는 확장 아트를 발견하고 바로 출력할 수 있게 하는 큐레이션·검색 레이어."
- 핵심 단서: "아는 수집가가 있음, 원하는 카드 번호에 해당하는 그림을 찾기 어려움" — 가장 구체적이고, 접근 가능한 첫 사용자가 있다.
- 반론: 병목은 아티스트 수가 아니라 기존 작품 수집·권리 확인·메타데이터 입력 → 전제 2 수정에 반영.
- 48시간 프로토타입: Next.js + Supabase, 목표 카드 100개 CSV 시드, 카드 번호 검색, 카드별 도안 목록(썸네일·아티스트·원본 링크), 초대 아티스트용 간단 업로드, 결과 없음 로그 + 요청 버튼, 클릭 측정. 로그인·커뮤니티·DPI 검증·PDF 엔진 생략.
- 이견: Codex는 "권리 불명확 파일은 링크만"을 리스크 회피로 제시했으나, Relic Castle은 비호스팅에도 내려갔으므로 링크는 법적 방패가 아니다. 링크 기본값의 진짜 이유는 아티스트가 원본 글의 소유와 노출을 유지한다는 점(설득 비용 감소)이다.

## Approaches Considered

- **A. 링크 전용 큐레이션 인덱스** — 가장 빠름(human ~1주 / CC ~반나절). 링크만으로는 보관 고통(원본 글 삭제·링크 깨짐)을 어떤 작품에 대해서도 풀 수 없어 기각. B도 대부분의 작품은 링크로 시작하므로, B가 A보다 나은 점은 (1) 허락받은 작품은 영구 보관되고 (2) 링크 상태를 점검해 죽은 링크를 감지하고 호스팅 허락 요청으로 전환하는 경로가 있다는 것이다. 링크 전용 작품의 보관 문제는 B에서도 감지와 전환까지만 해결된다.
- **B. 허락 기반 하이브리드 아카이브** — 선택.
- **C. IP 중립 인쇄 도구** — 사업화 층 후보이나 확인된 고통(발견)을 풀지 않고 실측이 선행돼야 해서 보류. B 안정화 후 재검토.

## Recommended Approach

**B. 허락 기반 하이브리드 아카이브** (human ~2~3주 / CC ~1~2일)

카드 번호로 찾으면 그 카드의 도안 목록이 나온다. 각 도안은 기본적으로 아티스트의 원본 글 링크로 연결되고, 아티스트가 허락한 경우에만 파일을 R2에 보관해 직접 다운로드를 제공한다.

### 일정: 검증 → 릴리스 1 → 릴리스 2

- **1주차 (코드 없음):** The Assignment가 전제 4의 1~2주 검증이다. 수집가의 실패 카드 10개와 아티스트 5명의 허락 결과로 진행 여부를 판단한다.
- **릴리스 1 (2주차, human ~1주 / CC ~1일):** 창업자 혼자 큐레이션해 등록한다. 링크 연결과, 허락받은 작품은 창업자가 직접 R2에 보관하는 것까지. 아티스트 셀프 업로드는 없다. 1호 수집가와 허락한 아티스트에게만 링크를 공유한다.
- **릴리스 2 (4주차 이후):** 초대 링크 셀프 업로드, 링크 상태 점검 자동화. **3주차 말에 판단한다.** 진행 조건은 두 가지다. (1) 1호 수집가가 실패 카드 10개 중 6개 이상의 도안을 사이트에서 찾았다. (2) 연락한 아티스트 중 5명 이상, 그리고 연락한 인원의 30% 이상이 등재에 동의했다. 둘 다 Assignment와 릴리스 1 첫 주만으로 측정할 수 있다. 출시 4주 기준인 방문자 클릭률은 릴리스 2를 막는 조건이 아니라 이후 방향을 점검하는 지표로 쓴다.

### 카드 식별

- **정본 키는 한글판 인쇄본**으로 한다: `(set_code, collector_number)`. 예: 한글판 `sv2a` + `201/165`. 한글판이 일본판과 같은 코드·번호를 쓰지 않는 세트는 한글판 코드를 정본으로 둔다.
- `card_aliases` 테이블에 같은 그림의 일본판·영문판 `(set_code, collector_number)`와 국·일·영 이름을 별칭으로 저장한다. 검색은 정본과 별칭 모두에 정확 매칭하고, 이름은 `pg_trgm` 부분 검색을 쓴다.
- 확장 아트는 일러스트를 기준으로 맞추므로 작품은 정본 카드 하나에 붙는다. 별칭으로 검색해도 같은 카드 페이지로 간다.
- 시드 CSV 컬럼: `set_code, collector_number, name_ko, rarity, illustrator, alias_set_code_ja, alias_number_ja, name_ja, alias_set_code_en, alias_number_en, name_en`. 별칭 컬럼은 비어 있어도 된다.
- 한글판·일본판 번호 체계가 실제로 어디까지 같은지는 시드 작성 중에 확인한다(Open Questions).

### 화면과 기능 (릴리스 1)

- 카드 시드: 1호 수집가와 카페 요청에서 나온 목표 카드(초기 ~100장), CSV 임포트.
- 카드 상세(허브): 실루엣 플레이스홀더(공식 이미지 없음), 규격 필터는 시드 작품이 있는 규격만 노출, 도안 타일(아티스트 닉네임 강조, `다운로드` 또는 `원본 글 보기 ↗`).
- **썸네일 규칙:** 썸네일은 아티스트가 `thumbnail_ok`에 동의한 경우에만 R2에 저장해 보여 준다. 카페 이미지를 직접 불러오는 핫링크는 쓰지 않는다. `link_only`이면서 썸네일 동의가 없는 작품은 규격 실루엣과 아티스트 이름만 있는 텍스트 타일로 보여 준다.
- **회원 전용 원본:** `artworks.source_visibility`(public / members_only)를 기록한다. 회원 전용 원본은 타일에 "카페 가입 필요" 라벨을 단다. 회원 전용이면서 호스팅 허락이 없는 작품도 등재는 하되, 지표에서 별도로 집계한다(Open Questions의 카페 정책 확인 전 임시 규칙).
- 빈 상태: "이 카드 도안 요청하기 · N명이 기다리는 중". 중복 방지는 익명 방문자 ID 쿠키(아래 측정 참고) 기준.

### 측정

- 익명 방문자 ID: 1st-party 쿠키에 무작위 UUID를 저장한다(로그인 없음). 고유 방문자와 재방문(서로 다른 날짜의 방문)을 이 ID로 집계한다. 측정용 이벤트에는 IP를 저장하지 않는다(신고 남용 방지용 24시간 해시 카운터만 예외, 권리·허락 절 참고).
- 이벤트: 검색어, 결과 없음(`search_misses`), 다운로드 클릭, 원본 링크 클릭, 요청. 모두 방문자 ID와 함께 기록한다.
- 1호 수집가의 재방문은 위 데이터에 더해 2주 뒤 직접 물어 확인한다.

### 권리·허락

- 작품별 기록: `consent_level`(link_only / hosted), `thumbnail_ok`, `source_url`, `source_visibility`, `consented_at`, 허락 근거(DM 캡처 또는 메시지 링크, 비공개 보관).
- **허락 철회·하향:** 아티스트는 DM 또는 사이트 푸터 연락처로 요청한다. 창업자는 48시간 안에 처리한다. hosted → link_only 하향이나 철회 시 R2 원본·썸네일 객체를 삭제하고, 행은 `consent_level` 변경 또는 `status=withdrawn`으로 남긴다. 변경 이력은 `consent_events`(작품, 이전→이후, 시각, 사유)에 기록한다.
- **R2 접근 모델:** 버킷은 비공개다. 다운로드는 서버가 매번 상태를 확인한 뒤 짧게 만료되는(예: 5분) 서명 URL을 발급하고, 공개 영구 URL은 만들지 않는다. 썸네일도 같은 방식이거나 상태 확인 프록시를 거친다. 따라서 행을 비공개로 바꾸면 새 URL 발급이 즉시 멈추고, 내림·철회 시에는 객체를 삭제한다.
- **신고 흐름:** 신고 버튼은 사유(권리자/본인 요청, 도용 의심, 기타)와 선택 연락처를 받아 `reports`에 저장하고 창업자에게 이메일로 알린다. 신고만으로 작품을 자동으로 숨기지 않는다. 같은 작품에 **서로 다른 IP 대역 3곳**에서 신고가 들어오면 자동으로 숨기고 검수 대기로 둔다(쿠키 ID는 쉽게 초기화되므로 기준으로 쓰지 않는다). 하루 신고 수는 IP 대역당 5건으로 제한한다. IP는 이 남용 방지에만 쓴다. IPv4 /24 또는 IPv6 /48로 자른 뒤 서버 비밀값으로 해시하고, 24시간 뒤 사라지는 카운터에만 보관한다. 이벤트 로그나 `reports`에는 쓰지 않는다. 권리자 요청은 창업자가 확인 후 즉시 숨기고 객체를 삭제한다. 잘못 숨긴 작품은 어드민에서 복구하며, 복구도 `consent_events`에 남긴다.

### 관리자와 업로드 보안

- 릴리스 1의 어드민은 창업자 한 명이다. Supabase Auth 이메일 로그인 + `admins` 허용 목록으로 `/admin` 전체를 보호한다(일반 사용자 로그인은 여전히 없음).
- 업로드(어드민 전용, 릴리스 1): Vercel 함수의 요청 본문 한도(~4.5 MB) 때문에 파일은 서버를 거치지 않는다. 서버가 `Content-Length`(최대 100 MB)와 `Content-Type`을 고정한 짧은 만료의 presigned PUT URL을 발급하고, 브라우저가 R2에 직접 올린다. 업로드가 끝나면 서버가 객체의 첫 16바이트를 range GET으로 읽어 매직 바이트(PNG·JPEG·PDF)를 확인한다. 불일치하면 객체를 삭제하고 행을 만들지 않는다. 다운로드는 서명 URL에 `Content-Disposition: attachment`를 붙여 내려보낸다.

### 링크 상태 점검

카페 글은 프레임이나 스크립트로 불러오고, 삭제된 글도 HTTP 200과 함께 오류 페이지를 돌려주는 경우가 많다. 그래서 HTTP 상태 코드만으로는 판단하지 않는다.

- 릴리스 1 (수동): 어드민 목록에서 창업자가 주 1회 각 원본 링크를 직접 열어 보고 상태(정상/삭제됨/권한 없음)를 손으로 표시한다. 등록 작품이 ~100개 수준이라 감당할 수 있다. 깨진 링크는 타일에 "원본 글이 사라졌어요"를 표시하고, "아티스트에게 호스팅 허락 재요청" 대상으로 올린다.
- 릴리스 2 (반자동, 공개 글만): 서버가 공개(`public`) 원본에 요청을 보낸다. 응답 본문에서 알려진 삭제·비공개 안내 문구를 찾으면 "의심"으로 표시하고, 창업자가 확인해 확정한다. 요청이 차단되거나 판단이 안 되면 "확인 필요"로 남긴다. 자동으로 숨기지는 않는다.
- 회원 전용 원본은 자동 점검이 불가능하다(항상 로그인 필요로 보임). 대신 등록할 때 호스팅 허락을 우선 요청하고, 허락이 없으면 월 1회 창업자가 카페 회원 계정으로 직접 확인한다.

# Design Review (plan-design-review, 2026-10-28)

Target: 이 문서. 시각 목업 없음(OpenAI 키 미설정). 아래 결정은 원본 128~132행의 디자인 방향 미정 상태와 와이어프레임을 대체한다.

## Design decisions

- **1A 방향 (D4):** "수집가의 작업대"로 확정한다. 카드 상세는 카드 번호를 시각 기준점으로 두고 작품을 하나씩 정렬한다. 3×3 속지 표현은 9포켓 작품 각각의 미리보기 안에서만 쓰고, 서로 다른 작품을 한 속지에 섞지 않는다. Codex의 "따뜻한 미색 + 형광 포인트" 팔레트는 채택하지 않는다(흔한 AI 팔레트). 규격 필터 전환은 결과 교체만 하고 작품 프레임 모양은 바꾸지 않는다.
- **2A 카드 상세 위계 (D5):**
  ```
  ┌ 워드마크 "확장 아트 아카이브"            [축소 검색창 ⌕] ┐   ① 어디인지 + 다시 찾기
  │ sv2a  201/165                     (큰 고정폭 숫자)       │   ② 내가 찾은 카드 (기준점)
  │ 리자몽 ex · SAR · 포켓몬 카드 151 · 일러스트 ○○          │
  │ ─────────────────────────────────────────────────────── │
  │ 확장 아트 도안 6개   [전체] [9포켓] [PSA] [BRG]           │   ③ 무엇이 있는지 + 거르기
  │ 작품 목록 …                                               │   ④ 작품
  └───────────────────────────────────────────────────────────┘
  ```
  카드 정보와 검색창의 테두리 상자는 없앤다. 위계는 글자 크기·간격·구분선 하나로 만든다. 중립 실루엣은 번호 블록 옆의 보조 요소로만 둔다.
- **3A 홈과 후보 목록 (D6):** 홈(`/`)은 워드마크, 제목 "카드 번호로 확장 아트 찾기", 큰 검색창(예시: `sv2a 201/165`, `리자몽`), "최근 도안이 등록된 카드" 6장의 번호 목록만 둔다. 후보 목록(번호만 입력·이름 검색 시)은 카드당 한 줄 표: 카드명 / 확장팩 / 세트·번호(고정폭) / 레어도 / 도안 수. 도안 수가 많은 순, 같으면 최신 확장팩 순. 도안 0개 카드도 목록에 남기되 "도안 없음"을 흐리게 표시한다.
- **4A 작품 표시 두 종류 (D7):** 썸네일 있는 작품은 위쪽 그리드 타일(미리보기 + @작가 + 규격 + 행동). 썸네일 없는 작품은 그 아래 한 줄 행: `@작가 · 규격 · 출처 도메인 · [원본 글 보기 ↗]`. 상태 표시는 행동 버튼 바로 옆 텍스트로: "카페 가입 필요"(members_only), "원본 글이 사라졌어요"(link_status=삭제됨, 버튼 비활성). hidden·withdrawn 작품은 목록에 나오지 않는다.
- **5A 빈 규격과 요청 (D8):** 원본 86행 "시드 작품이 있는 규격만 노출"을 대체한다. 지원 규격(9포켓·PSA·BRG) 칩은 항상 보이고, 0개 규격 칩은 흐리게 표시하되 선택할 수 있다. 빈 상태는 그 규격을 선택했을 때만 결과 자리에 나온다("전체"에서는 나오지 않음). 카드 전체에 도안이 0개면 "전체"에서도 같은 빈 상태. 문구: 제목 "이 카드의 BRG 도안 찾아 주세요", 보조 "기존 도안을 찾아 등록할 때 참고해요", 버튼 "찾기 요청". 누른 뒤: "요청이 기록됐어요 · 등록되면 이 페이지에 나타나요"로 바뀌고 버튼 비활성(같은 방문자 ID 재방문 시에도). 대기 수는 해당 카드·규격 기준 3명 이상일 때만 "N명이 기다리는 중"으로 표시.
- **6A 상태 표 (D9):**

  | 기능 | 로딩 | 빈 상태 | 오류 | 성공 | 부분 |
  |---|---|---|---|---|---|
  | 검색 | 검색창 오른쪽 작은 진행 표시, 이전 결과 유지 | 카드 못 찾음: "‘{입력}’에 맞는 카드를 못 찾았어요" + 예시 형식 2개 + "이 번호로 찾기 요청"(search_misses) | "검색이 잠시 안 돼요. 다시 시도" 버튼 | 1건 → 카드 상세 이동, 여러 건 → 후보 표(3A) | — |

  | 원본 글 보기 | — | — | 삭제됨: 버튼 비활성 + "원본 글이 사라졌어요" | 새 탭으로 열기 | members_only: "카페 가입 필요" 사전 표시 |

  | 신고 | 제출 버튼 "보내는 중…" | — | 저장 실패: 입력 유지 + "보내지 못했어요. 다시 시도" | "신고가 접수됐어요. 확인 후 처리할게요" | 메일 발송 실패는 사용자에게 성공으로 표시(reports 저장 기준) |

  서명 URL은 클릭 시점에 발급하므로 만료 링크를 화면에 남기지 않는다.
- **7A 인쇄 안내 (D10):** 다운로드가 시작되면 버튼 아래에 한 줄을 남긴다: "인쇄할 때 크기는 ‘실제 크기(100%)’로, ‘페이지에 맞추기’는 끄세요" + 해당 규격 치수(9포켓 조각 63×88 mm 등, 규격 라벨 기준). 닫기 가능, 같은 세션에서 반복 표시하지 않는다.
